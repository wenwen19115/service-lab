# Service Lab

本地服务模拟测试平台。用于测试设备 OTA 升级，也可以配置普通 HTTP 接口的响应。

后端使用 Go，界面使用 React + TypeScript。前端构建后嵌入可执行文件，运行时不需要 Node.js、数据库或外部 Web 服务器。Windows、macOS、Linux 可以分别构建。

## 当前功能

- 上传支持格式的应用固件，读取镜像内置版本、文件大小和 SHA256。
- 固件库支持搜索、排序、版本编辑、SHA256 复制和原始文件下载。
- 发布前确认目标版本，明确标注正在发布的固件；支持停止发布和场景配置。
- 固件可移到回收站并恢复；正在发布的固件不能删除。
- 模拟正常升级、无更新、检查失败、下载失败和下载中断。
- 转发上游 OTA 响应，只替换 `firmware` 字段，保留其他配置、激活信息和时间。
- 转发 OTA 激活请求。
- 配置模拟接口的方法、路径、响应状态码、Content-Type、响应体、自定义响应头和延迟。
- 正常、异常、延迟场景模板；规则可启停、复制和 JSON 导入导出。
- 内置本地接口调试器，发送请求后查看状态、耗时、响应头和内容。
- 总览展示请求活动、当前发布和实时传输；设备页展示请求中识别出的设备与上报版本。
- 请求记录支持分类、设备和结果筛选、搜索、分页与导出。
- 查看最近 300 条请求；固件下载从开始就显示，按秒刷新传输进度、字节数、速率、完成或中断状态。
- 请求详情展示下载过程和响应头，请求与响应 JSON 自动缩进。无 Device-Id 的下载请求会按客户端 IP 关联最近 30 分钟内的 OTA 检查记录。
- 下载字节数指服务端写入连接的数据量，不表示设备写入 Flash 或升级成功。

配置、固件和最近 300 条请求保存在数据目录，重启后继续使用。请求历史每 2 秒合并写入一次；强制结束程序可能丢失最后几秒的记录。重启时未结束的传输标记为中断，不会显示成已完成。默认没有发布固件，OTA 场景为“无更新”。

## 双击启动

Windows 下双击 `dist/service-lab.exe`，程序会在后台启动服务并打开默认浏览器。再次双击会打开已有服务的页面，不会启动第二个实例。

如果 8080 被其他程序占用，会显示错误窗口。运行日志保存在数据目录的 `service-lab.log`。需要更换端口时，在终端执行：

```powershell
.\dist\service-lab.exe -addr 0.0.0.0:8081
```

默认数据目录跟随程序位置，不取决于启动时的工作目录：程序放在 `dist` 中时使用上一级目录的 `data`，放在其他目录时使用程序旁的 `data`。仍可用 `-data` 指定目录。

后台运行或开发时，不希望打开浏览器可以加 `-open=false`。Windows 发布程序不显示控制台窗口；需要停止时，在任务管理器中结束 `service-lab.exe`，或者在开发期间使用终端构建的控制台版本。

## 构建和启动

开发环境需要 Go 1.24 或更高版本、Node.js 22 和 npm。

先构建前端，再编译后端：

```sh
cd web
npm ci
npm run build
cd ..
go build -o dist/service-lab .
```

Windows 发布版使用以下命令隐藏控制台窗口：

```powershell
go build -ldflags "-H=windowsgui" -o dist/service-lab.exe .
```

```sh
# macOS / Linux
./dist/service-lab -addr 0.0.0.0:8080 -data ./data
```

```powershell
# Windows
.\dist\service-lab.exe -addr 0.0.0.0:8080 -data .\data
```

浏览器打开 `http://localhost:8080`。界面和设备接口使用同一个端口。

侧边栏“关于”展示工程版本、编译时间和新手使用说明。直接执行 `go build` 时如未注入 `service-lab/internal/lab.BuildTime`，编译时间显示为“未记录”。工程版本在 `internal/lab/build.go` 中维护，与设备固件版本独立。

开发前端时，先启动 Go 服务，再在 `web` 中执行 `npm run dev`。Vite 将管理接口请求转发到 `127.0.0.1:8080`。设备仍访问 Go 服务的 8080 端口，不使用 Vite 地址。更改前端后，需要重新构建前端和 Go 程序，发布版才会更新。

## 设备 OTA 测试

### 1. 连接网络

电脑和设备接入同一局域网，允许设备访问电脑的 8080 端口。手机热点、访客网络可能隔离客户端，连接同一个 Wi-Fi 不代表一定能互相访问。

在 OTA 页选择设备能访问的电脑 IP。电脑有多个网卡时，不要选到虚拟网卡，也不要给设备填写 `localhost` 或 `127.0.0.1`。

### 2. 只改设备的 OTA 地址

在平台中复制设备可访问的 OTA 地址，替换设备项目中的 OTA 地址配置。例如：

```c
const char ota_url[] = "<从平台复制的 OTA 地址>";
```

设备端不增加测试开关，不修改检查更新、下载、写入和重启流程。只将此配置编译进应用并烧录一次。

测试固件也需要使用同一测试地址，否则升级重启后会重新请求生产 OTA。测试结束后恢复生产地址并重新构建。平台不会修改设备项目或设备版本号。

### 3. 上传并发布固件

在“OTA 管理”的固件库上传应用 `.bin`，支持拖放或选择文件。上传后不会自动发布。

- 点击固件卡片的“发布”，确认后按已保存的连接设置，以正常升级场景发布该固件。
- 也可在“升级场景”中选择固件、测试场景和服务地址，再点击“应用设置”。未保存的修改会显示在页面底部。
- 页面顶部显示当前实际发布的版本，固件列表标注“正在发布”。
- “停止发布”会切换到无更新，并清除发布固件选择。
- 删除会把文件移到回收站，可恢复；恢复后不会自动发布。正在发布的固件需先停止发布或切换到其他固件才能删除。

上传时会弹出版本输入框，默认填入镜像内置版本。上传后可通过“编辑版本”修改发布版本。发布版本用于 OTA 检测响应，镜像版本来自文件本身，平台不改写 .bin。发布版本需高于设备当前版本。设备如果曾选择“忽略此版本”，需解除忽略或使用其他目标版本。

上传文件必须是 app 镜像，不是全量合并固件、bootloader、分区表或资源分区。16 MiB 是平台上传上限，不是设备分区大小；例如 5 MiB 应用分区只能使用小于该分区容量的固件。平台对镜像只做头部检查，最终有效性由设备的 OTA 校验判断。

发布版本和镜像版本不同时，升级后设备仍报告镜像版本，可能反复提示更新。这种设置适合测试更新提示或下载流程。完整升级验证建议使用对应版本的真实固件；平台不会生成或改写新版固件。发布版本使用数字格式，例如 2.0.62，最多 31 个字符。

### 4. 配置上游转发

默认启用上游转发。使用前请确认上游地址与设备协议匹配：

1. 将设备原始请求发给配置的上游地址。
2. 保留上游 JSON 返回字段。
3. 删除或替换 `firmware` 字段。
4. 将固件下载地址指向本地平台。

OTA 激活请求也会转发。上游不可达或返回无效 JSON 时，平台返回错误，不使用空配置代替。

仅测试升级、不需要上游配置时，可关闭转发。关闭后检查接口只返回模拟固件信息和时间，不返回上游连接参数。

### 5. 观察结果

在设备端触发检查更新并确认升级，具体操作以设备界面或控制方式为准。请求记录中应先出现 OTA 检查，再出现固件 GET 请求。

成功需要同时验证：

- 设备提示的目标版本正确。
- 下载进度完成，固件校验通过。
- 设备重启并运行目标版本。
- 再次检测时不再提示同一版本。

平台只能确认请求和文件传输情况。下载完成不等于设备已升级，最终结果以设备版本和串口日志为准。

## 测试场景

- **无更新**：从返回中移除 `firmware`。不改变上游的其他字段。
- **正常升级**：返回所选固件的发布版本和本地下载地址。
- **检查失败**：检查接口返回 HTTP 503，不请求上游。
- **下载失败**：检查正常返回固件，下载该发布固件时返回 HTTP 503。
- **下载中断**：下载响应声明完整文件长度，只传输一半内容后结束连接。
- **响应延迟**：检查接口增加 0–30000 毫秒延迟，可以与上述场景组合。

已知限制：当前下载中断使用同一发布场景控制，正在下载时修改场景可能影响后续请求。测试过程中保持配置不变。完整断电恢复和 bootloader 回滚需要结合真实硬件验证。

## 普通接口模拟

在“接口模拟”中添加规则，例如：

- 方法：`POST`
- 路径：`/mock/device/status`
- 状态码：`200`
- Content-Type：`application/json`
- 响应内容：`{"code":0,"message":"ok"}`

规则按方法和路径精确匹配，查询参数不参与匹配。方法 `*` 表示匹配任意方法。规则按列表顺序匹配，先添加的规则优先。

支持自定义响应头，禁止自行设置 Content-Length、Transfer-Encoding 等协议控制头。204、304 和 HEAD 请求不发送响应体。

点击接口卡片的“调试”，可填写方法、路径、请求头和请求内容并发送。调试器只访问当前 Service Lab 的设备接口，不允许请求外部 URL 或管理 API；响应最多显示 1 MiB。调试请求也进入请求记录。

导入文件使用规则数组格式，可直接使用平台导出的 JSON。导入会追加规则；方法与路径重复时整批拒绝，原规则不变。最多保存 100 条规则。

暂不支持路径通配符、请求体条件匹配、动态模板或通用反向代理。接口模拟与 OTA 独立，不需要修改 OTA 的设备协议。

保留路径：`/`、`/api*`、`/firmware*`、`/assets*`，以及平台 OTA 接口的路径前缀。

## 数据和运行范围

`-data` 指定的数据目录中包含：

```text
data/
├── config.json          OTA 设置、固件元信息和接口规则
├── events.json          最近 300 条请求及传输记录
├── service-lab.log      运行日志
├── trash/               已移到回收站的固件
└── firmware/
    └── <固件ID>.bin
```

配置保存后立即生效。请求体最多记录前 8 KiB，超过部分截断。记录选定的常用请求头，不记录 Authorization；请求体仍可能包含设备相关数据。

“服务设置”可查看数据目录、启动时间、历史记录保存状态和访问地址，并导出配置备份。配置备份不包含固件文件和请求历史；完整迁移请复制整个数据目录。

设备列表来自现有请求记录，不是实时心跳。“最近有请求”只表示 2 分钟内访问过服务，固件发送完成也不代表设备已经刷写成功。

管理页面提供蓝灰色系的白天、黑夜模式，支持窄屏布局。右上角可切换模式；首次打开跟随系统，手动选择后会在当前浏览器中记住设置。顶部可暂停自动刷新，方便检查数据；暂停只影响页面刷新，设备服务继续运行。

平台面向可信局域网，没有账号和访问权限管理。默认监听所有网卡，局域网内能访问端口的客户端也能访问管理界面。不要直接作为公网生产服务；需要远程使用时，先增加认证和 HTTPS。只允许本机访问时使用 `-addr 127.0.0.1:8080`，此时外部设备无法连接。

## 资源传输测速

上传字体或书籍文件（最多 64 MiB），服务生成大小、SHA256、下载地址和默认封面，也可上传 PNG/JPEG 自定义封面。文件上传不转换原始内容，封面统一缩放为 240×320 灰度 PNG。

在“接口模拟”页的“资源传输接口”模块，修改列表、确认及下载前缀后保存即可立即生效。可直接粘贴完整 URL，服务仅提取其中路径；主机仍使用当前服务器。配置自动保存，重新启动后继续使用，可一键填入默认值。

默认通用测试接口：

- `GET /transfer/resources`：返回 `code:0` 和 `data` 资源数组，每项包含 `id`、`type`、`name`、`size`、`sha256`、`downloadUrl`、`coverUrl`。
- `GET /resources/{id}`：下载原始文件，支持 HEAD 和 Content-Length。
- `GET /resources/{id}/cover.png`：获取资源封面。
- `POST /transfer/confirm`：提交 JSON `{"resourceId":"资源编号"}` 确认接收，仅对当前客户端隐藏资源，重复确认成功。客户端通过 Device-Id 请求头标识，缺省使用来源 IP。

客户端自行完成列表获取、下载和接收确认，不绑定特定产品的接口配置或业务流程。点击“重新提供”清除确认记录，便于重复测速。资源及元信息保存在数据目录，最近 300 条请求与传输记录可在界面查看。

资源下载地址根据列表请求的协议和 Host 生成，独立于 OTA 对外地址配置。电脑与客户端需网络互通。服务端耗时不等于端到端耗时，文件发送完成不代表客户端保存完成。

## 网络阻塞诊断

服务运行日志 `data/service-lab.log` 新增 `[NETDIAG]` 标记，包含连接接入/关闭、完整 HTTP 请求头到达、请求体开始读取/结束、响应头写入和响应结束。日志使用毫秒级时间戳，只记录元数据，不输出请求体或 Authorization。OTA 请求会在读取请求体前先进入页面记录。

“接口模拟”页的“请求诊断”模块可下载最近 1 MiB 诊断日志。原始完整日志仍位于数据目录。连接日志包含管理页面的浏览器连接，分析时按设备 IP、源端口及 `X-Diagnostic-Id` 筛选。

设备诊断固件串口日志同样带 `[NETDIAG]`。OTA 请求携带诊断编号；设备打印的 TCP 本地端口可对应服务器日志中的 remote 端口。设备时间为启动后的相对时间，服务器时间为本机时间，不能直接相减；优先用诊断编号和端口对齐。

观察服务端最后出现的阶段：

- `connection state=new` 而没有 `request_begin`：连接已被服务接受，但尚无完整 HTTP 请求头。
- `request_begin` 后请求体读取不结束：检查设备发送状态及请求长度。
- `upstream_begin` 后长时间没有 `upstream_headers`：上游服务尚未返回响应头。
- `response_end` 成功但设备未收到回复：需要结合设备日志及网络抓包检查回复方向。

TCP 握手前的 SYN/ARP 不会进入服务端连接日志。服务器没有连接日志时，应结合设备日志或独立抓包工具判断；这些日志不能确认无线空口重传次数。设备超时和重试策略由设备固件决定。

## 重启服务

在“服务设置”点击“重启服务”，当前实例会停止接收请求、等待已有请求结束（最多10秒），关闭并重新加载配置和请求历史，然后恢复原端口。页面自动等待恢复并刷新，配置及资源不变。正在传输的文件可能中断，建议空闲时操作。

## 服务模块与接口配置

侧栏“服务”可展开OTA服务和资源传输。OTA服务管理固件、版本和响应场景；资源传输管理文件与封面。两者的接口地址统一在“接口模拟”中独立配置，保存即时生效。OTA预置检测接口，原配置升级后保留现有地址，也可填入通用路径 `/ota`。激活入口随检测路径追加 `/activate`。修改路径后需同步调整客户端；旧路径不再作为该服务接口生效。
